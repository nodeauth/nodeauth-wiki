# 端对端加密 (End-to-End Encryption)

NodeAuth 在其核心身份识别资产（2FA 密钥）上实现了标准的 **端对端加密（End-to-End Encryption, E2EE）**。为了确保用户理解数据的安全流转，我们将这一架构的加密原理拆解如下：

## 1. 什么是端对端加密？

在安全领域，端对端指的是加密在应用的一个“端”（用户的浏览器）发生，解密在另一个“端”（同样是用户的浏览器）发生。中间经过的所有节点（包括 NodeAuth 服务器、数据库、网络连接等）都无法解密或窥探原始数据。

- **起点（浏览器）**：在你保存验证码种子的一瞬间，数据已经在本地被掩码钥匙（Masking Key）加密。
- **中转站（服务器/数据库）**：服务器收到的已是密文，它无法解密，只能作为“瞎子存储器”代为保管。
- **终点（浏览器）**：只有当你再次登录并验证身份后，加密的数据流回到你的本地环境中，才会被解开。

## 2. 混合加密策略 (E2EE + SSE)

为了在 **极致安全** 和 **极致体验** 之间取得平衡，NodeAuth 采用了分层加密策略：

| 数据类型 | 加密方式 | 目的/优势 |
| :--- | :--- | :--- |
| **2FA 密钥 (Secret)** | **端对端加密 (E2EE)** | 这里的资产价值最高。即使服务器被黑或管理员意图窥探，也物理上无法看到你的种子，实现了真正的零知识（Zero-Knowledge）。 |
| **元数据 (应用/账号名)** | **服务器端加密 (SSE)** | 这部分由服务器替你加密。允许服务器在解密态下执行**搜索、排序、分页**。这保证了哪怕你有数百个账号，系统依然能保持丝滑的响应速度。 |

## 3. 安全总结

NodeAuth 的端对端加密机制确保了：你的 2FA 种子在整个网络传输和存储生命周期中，都是只有你自己能解开的。这实现了与 1Password、Bitwarden 等商业级密码管理器完全对等的核心资产保护级别。
